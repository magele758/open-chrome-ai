# 点播中文配音 v2

侧栏「同声传译」现在运行 planned-interpret.js。旧 interpret.js 保留给录音路径及回归测试，侧栏不再用 5 秒切片驱动逐段翻译。

## 默认异步起播

下载音轨后，优先处理当前播放位置的 12 秒，再以最多 24 秒窗口向前准备。转写与翻译生产口播稿，另一条任务持续合成配音，播放独立运行。连续可播放内容达到 3 秒即可恢复画面，不等待全文转写、全文摘要或全部配音。3 秒是已准备内容的播放时长，不是承诺 3 秒完成准备。

全文说话人识别、音乐分类与伴奏分离在后台运行，完成后用于后续窗口，并撤销尚未播放的临时配音重新按说话人切分、生成；已播放内容和正在播放的句子保留。分析尚未完成时，未知音频仍送 ASR，数字静音直接跳过；此时不能保证跳过所有纯音乐，也不能保证已有完整的说话人编号。优先使用对应说话人的可靠参考音，其次使用识别到讲话的当前片段，无法取得有效参考时才退回配置音色。ASR 返回的说话人编号仅在其识别窗口内复用；未标注身份的句段不合并，避免把不同人的参考音混在一起。后台得到可靠说话人样本后更新尚未播放的片段。

翻译使用当前窗口和前面最多 12 条、6000 字符的双语上下文，逐步积累术语与指代，不再先阅读全文。拖动后，正在处理的请求结束就优先处理新位置；已完成内容继续缓存。未处理区域不视为空白，缓冲耗尽时暂停画面。后台预取范围有界，避免远处任务挤占当前位置；预缓存设置影响向前准备范围，不挡住首次起播。

**剩余前置等待：原音轨仍需完整下载。** 这次消除了整条分析、转写、翻译及配音的起播屏障，尚未实现边下载边处理。实际起播时间取决于下载与首窗口 ASR、翻译、TTS 服务耗时，尚无一小时真实媒体的耗时实测。

## 可选完整准备流程

1. 本机媒体服务下载完整 16kHz 单声道音轨，保留全部时间。
2. pyannote community-1 对整条音轨做说话人标注，使用重叠标注，不强行把抢话归给某一个人。
3. AST AudioSet 分类检查音乐；数字静音单独检测。只有无说话人且音乐置信度 >= 0.65、人声相关类别 < 0.05 才标记为纯音乐。其他未知声音继续送 ASR，不能按音量把轻声讲话丢掉。
检测到讲话区间混有音乐（music >= 0.1）时，使用本机 Demucs htdemucs 分离伴奏；伴奏缓存与原音轨时间一致，配音播放时单独跟随视频进度，画面暂停时伴奏也暂停。

4. 相邻同一说话人的声音合并为最长 30 秒识别窗口。原稿按源顺序保存，时间为原音轨绝对时间；识别请求可并发两项。检测到讲话而 ASR 返回空结果会报告错误，不把缺失稿件伪装为完整结果。
5. 先按章节整理全文上下文，再按不超过 90 秒/5000 字符的批次翻译。每个原文 ID 必须按源顺序恰好出现一次，禁止跨人、跨空档合并；中文单段最多 500 字、覆盖原音频最多 30 秒。长文上下文采用分层压缩。
6. 每位说话人选择一条至少 3 秒、无重叠且低背景音乐的参考音。没有可靠长样本时尝试当前非重叠讲话片段，质量检查不通过才使用用户配置音色；不借用其他人的参考音。
7. 配音测量实际时长，语速最多额外加快 12%，最多借用后续 1.5 秒空档，不覆盖下一轮讲话；仍过长则暂停画面，让整句播放完。

## 播放与修改

- 默认快速异步起播；旧设置首次加载会迁移到此模式。完整配音后播放保留为用户主动选择。
- 另保留全文翻译后边配音边播放模式，连续缓存为 5–120 秒，默认 30 秒。所有模式都不能跨过失败或未处理片段凑缓存。
- 纯音乐、静音和未配音空档保留原时间与原声。WebAudio 路径切换原声时做 80ms 淡入淡出。
- 用户暂停优先于自动恢复；准备阶段维持视频暂停；拖动只改变播放位置和生成优先级，不清空成品。
- 侧栏「修改本句配音」保存用户修改，只重做该句并回到该句起点。修改记录及不同音色配置参与缓存关联。
- 原稿、译稿、用户修改、逐段音频分层保存在 IndexedDB，7 天有效；ASR/翻译中间成果即时保存，失败可重试。密钥不写入缓存键。

## 本机依赖

```sh
conda run -n pagelens-media python -m pip install -r tools/requirements-audio.txt
conda run -n pagelens-media python tools/media_helper.py --ensure
```

首次使用需要在 Hugging Face 账户接受 [community-1 模型条件](https://huggingface.co/pyannote/speaker-diarization-community-1)，并使启动媒体服务的环境能读取 HF_TOKEN。令牌只用于模型下载，不传给浏览器。模型下载后使用本机缓存。安装与验证使用 pyannote.audio 4.0.7、transformers 4.57.6；依赖范围见 requirements-audio.txt。重启旧媒体服务后健康接口版本应为 4。

伴奏分离使用 Demucs 4.0.1 / htdemucs。

模型：[pyannote.audio](https://github.com/pyannote/pyannote-audio)、[MIT AST](https://huggingface.co/MIT/ast-finetuned-audioset-10-10-0.4593)。处理在本机 CPU 进行，音轨不会发给这两个模型的托管服务；ASR、文本翻译、TTS 仍使用用户设置的服务。说话人是视频内的匿名编号，不代表已识别真实身份。

## 当前边界

- 这是点播流程，不支持未结束的直播。
- 混合音乐使用 Demucs 分离；分离可能残留原人声或损伤乐器，不能保证录音室级效果。没有被检测出的弱背景音乐可能随原声一起静音。
- 重叠讲话被标注并避免混用音色，但尚不能保证从混合声音中恢复每个人的每句话。
- 句段时间戳来自 ASR；缺少结束时间时使用窗口/下一段边界估计，不宣称逐字强制对齐。
- 自动检查能发现结构性的漏段/重复/跨人合并，不能证明翻译语义绝对无误。校对可通过修改本句完成。
- 无可靠音色样本且用户未配置参考音时会明确报错；不会冒充已生成稳定多人音色。

新回归覆盖完整时间覆盖、音乐跳过、说话人边界、抢话、参考音选择、原文 ID 校验、连续秒数缓存、全文与译稿缓存、完整/边准备边播模式、用户暂停、长配音、缓冲不足、拖动复用、修改单句及取消清理。

异步回归使用一小时模拟音轨，故意阻塞全文分析及第二窗口识别，验证首段照常播放、未知区间暂停、拖动优先处理新位置与取消清理。

音色回归覆盖 A→B→A 对应参考音、固定音色只作兜底、跨窗口说话人编号隔离，以及后台分析完成后重新生成排队片段并保留正在播放的句子。未完成说话人分析、ASR 分段跨人或参考音太短时，仍不能保证音色准确。

## 翻译分段错误恢复

批量翻译要求每个原文 ID 独立返回。模型若跨说话人合并、漏段或返回错误结构，在两次校验尝试后自动按原句重新翻译，保留相邻上下文、时间戳和说话人；不把错误的合并译文按字数硬拆。成功的单句立即缓存，服务鉴权或网络错误不会扩散成逐句请求。

识别语言是原视频语言，与中文配音输出语言不同；观看多语言视频时应选择自动识别。把英文音频强制指定为中文可能造成原稿乱码和幻觉，后续翻译不能补回丢失的原意。
